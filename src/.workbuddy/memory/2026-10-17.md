## 新增 ROS 2 包：port_camera_publisher（Jazzy）

路径：`/home/y/ros2_ws/src/port_camera_publisher`

需求：从"传输端口"采集图像，发布到 `/video`。

实现（ament_python）：

- `video_publisher`：OpenCV 打开 RTSP / HTTP-MJPEG / USB 索引 / 视频文件。
  独立读线程只留最新帧 + rclpy 定时器发布；断流自动重连；
  网络与文件走 `CAP_FFMPEG`、摄像头走 `CAP_V4L2`（避免 CAP_ANY 误选 GStreamer 打不开）；
  本地文件按源 FPS 节流，可当假相机联调。
- `tcp_jpeg_receiver`：监听 TCP 端口，按 FFD8/FFD9 切 JPEG 帧（对端主动推流场景）。
- `check_video`：订阅体检（fps/分辨率/编码），可存一帧。
- 话题：`/video`(Image, 默认 bgr8) + `/video/compressed`(JPEG)。
  QoS 默认 BEST_EFFORT + KEEP_LAST(1)。
- launch ×2、config ×2、README。

验证（本机 Humble，用 `PYTHONNOUSERSITE=1` 绕过 numpy 冲突）：

- 640x480 视频源发布稳定 10.0 fps，订阅端收到 Image 与 CompressedImage，frame_id= camera_link。
- TCP 节点：15 fps，320x240，客户端断连/重连正常。

## 端到端复测与两处修正

- `_open_capture` 改为显式后端：网络/文件走 `CAP_FFMPEG`，摄像头走 `CAP_V4L2`，再回退 `CAP_ANY`。
  原因：`CAP_ANY` 会误选 GStreamer 后端，直接报 `no source element for URI` 并放弃。
- 本地视频文件按源 FPS 节流（`CAP_PROP_FPS`），否则 300 帧 0.4s 读完 → 一直重连，
  无法当"假相机"联调。
- 实测：视频源 15.0 fps 稳定发布，落盘 480x640x3 正常；TCP 节点 60 帧 @10fps 推流，
  订阅端收到 52 帧、320x240 bgr8 正确。
- 640x480 在沙箱内订阅端只有约 1 fps，是 DDS 回环丢大包；320x240 稳 10 fps，
  说明代码无问题，容器（host 网络 + `ipc: host`）不会复现。

### 关键坑（已修）

- **`-p source:=0` 会抛 `InvalidParameterTypeException`**：命令行 `0` 被按 YAML 解析成
  INTEGER，而参数按 STRING 固定声明就会崩（launch 传 `ParameterValue(..., str)` 不触发）。
  解决：新增 `port_camera_publisher/utils.py`，所有参数用
  `ParameterDescriptor(dynamic_typing=True)` 声明，读取时自行 `str()/int()/float()`；
  布尔值统一走 `as_bool()`（避免 `bool("false") == True`）。三个节点都已改。
- 摄像头源只走 `CAP_V4L2`，不再回退 `CAP_ANY`——否则每次重试多刷一屏 GStreamer warning。
- 宿主没有 `/dev/video*` 和 D435i，真机未验证；只做了 launch 结构静态校验
  （`generate_launch_description()` 能构建、remap/参数正确）+ 通用节点回归。
