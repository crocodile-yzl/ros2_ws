## 二、阶段一：Jazzy 兼容性评估（结论：可低成本移植）

- 官方未声明支持任何具体发行版，代码风格面向 Humble 时代（C++14）。
- **二进制层**：SDK 预编译库依赖宽松（GLIBC_2.17 / GLIBCXX_3.4.15 / libusb-1.0），Ubuntu 24.04 向后兼容，无障碍。
- **代码层**：未使用 Humble→Jazzy 之间被移除的 API（`get_parameter_or`、`ament_target_dependencies`、`image_transport`、`tf2_ros` 等均保留）。
- **移植需改**：`CMAKE_CXX_STANDARD` 14→17；`<eigen3/Eigen/Geometry>` 改为 `<Eigen/Geometry>`。
- **硬限制**：SDK 仅有 x86-64 版本，ARM 平台（Jetson 等）无法使用，需向厂商索取对应架构库。

## 三、阶段二：编译修复（此前编译一直失败的根因）

1. **`~/ros2_ws` 的 `build/install/log` 目录属主异常**（`nobody:nogroup`，不可写）→ 这就是旧 install 目录里没有可执行文件、节点无法启动的根本原因。
   解决：改用新目录构建，产物在 **`install_y`**：
   ```bash
   cd ~/ros2_ws
   colcon --log-base log_y build --packages-select berxel_camera_ros2 \
          --build-base build_y --install-base install_y
   ```
2. **Python 解释器劫持**：CMake 缓存了托管版 Python 3.13（缺 `catkin_pkg`）导致 configure 失败。
   解决：保证 `/usr/bin/python3`(3.10) 在 PATH 中优先，并删除 build 缓存目录后重新构建。
3. **结果**：编译成功（仅 3 个无害 warning：未使用变量 ×1、符号比较 ×2），launch 验证 OK：SDK 加载 `libBerxelUvcDriver.so` / `libBerxelNetDriver.so` 成功，libusb 热插拔回调注册成功。

## 四、阶段三：启动环境配置

## 七、遗留问题与建议

1. **代码 bug（未修，建议后续修复）**：
   - `updateCameraInfo()`：`m_cameraInfo[type].distortion_model.at(4) = ...` 应为 `d.at(4)`（k3 畸变系数写错字段，且会截断字符串，影响深度-彩色配准精度）；
   - 深度回调：`m_cameraInfo[...].binning_x = depth_image->height` 笔误（应为 width 相关逻辑）。
2. **旧目录清理**：`~/ros2_ws/{build,install,log}` 已废弃（属主异常），确认 `install_y` 稳定后可删除；或 `chown` 修复属主后回归默认目录名。
3. **conda 长期方案**：建议 `conda config --set auto_activate_base false`，避免每次手动 deactivate。
4. **想开彩色流**：`stream_type: 2` → `3`；想看彩色点云再开 `enable_align: true`。
5. **网络隔离**：实验室局域网内其他 ROS 2 设备互相可见（/imu 等），建议团队统一设置 ROS_DOMAIN_ID。
